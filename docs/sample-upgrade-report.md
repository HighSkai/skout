## Will break (1)

Lines that use syntax the target version no longer has. Skript will refuse to load them.

- **[scripts.sk:6](../server/test/fixtures/upgrade/scripts.sk#L6)** `send "Last used %last usage date%" to player`
  - This line seems to use 'Cooldown Time/Remaining Time/Elapsed Time/Last Usage/Bypass Permission' (`[the] last usage [date] [of [the] (cooldown|wait) [(of|for) [the] [current] command]]`), which Skript 2.17.1 no longer has.

## Functions that will fail to register (2)

Skript reports these when the script loads, and every call to the function then fails too.

- **[scripts.sk:12](../server/test/fixtures/upgrade/scripts.sk#L12)** `function entity(id: uuid) :: entity:`
  - Skript 2.17.1 adds a built-in function 'entity(uuid: uuid)' with the same argument types as your 'function entity(id: uuid) :: entity', so yours fails to register ("already exists").
  - ↳ Rename your function, or make it a local function.
- **[scripts.sk:15](../server/test/fixtures/upgrade/scripts.sk#L15)** `function grow(t: structure type, at: location):`
  - Skript 2.17.1 has no type 'structure type' (used as the parameter 't'), so Skript reports "Cannot recognise the type" and the function 'grow' fails to register.
  - ↳ It is now called 'tree type'.

## Behaviour changes (3)

The syntax still exists but works differently. From Skript's release notes.

- **[scripts.sk:3](../server/test/fixtures/upgrade/scripts.sk#L3)** `permission message: &cNo.`
  - Skript 2.17 deprecates the 'permission message' command entry and ignores it: a player without permission now gets Minecraft's "unknown command" instead. ([release notes](https://github.com/SkriptLang/Skript/releases/tag/2.17.0))
  - ↳ Check the permission at the start of the trigger and send the message yourself, e.g. `if player does not have permission "x": send "…" to player` then `stop`.
- **[scripts.sk:5](../server/test/fixtures/upgrade/scripts.sk#L5)** `send "Run by %executor%" to player`
  - In Skript 2.17 'the executor' returns the command's executor, which can differ from the sender (for example with /execute as). ([release notes](https://github.com/SkriptLang/Skript/releases/tag/2.17.0))
  - ↳ If you meant whoever ran the command, use 'sender' (or 'player') instead.
- **[scripts.sk:10](../server/test/fixtures/upgrade/scripts.sk#L10)** `set chat format to "[player]: [message]"`
  - Skript 2.16 deprecates the [player] and [message] placeholders in the chat format expression. ([release notes](https://github.com/SkriptLang/Skript/releases/tag/2.16.0))
  - ↳ Use the 'player' and 'chat message' expressions inside %…% instead, e.g. "%player%: %chat message%".

## How this was checked

Each line was matched against the syntax of Skript 2.15.4 and of Skript 2.17.1, using a port of Skript's own pattern matcher. A line that matched before but matches nothing after is reported as breaking. Function signatures were checked against the types and built-in functions of the target, and known behaviour changes come from Skript's release notes.

Limits: Skout cannot parse the expressions inside a pattern's `%slots%`, so a removed expression is only found when its wording is distinctive. Addon syntax is only checked if its syntax dump is loaded (`skout.syntaxDumps`). Test on a copy of your server before upgrading the live one.
